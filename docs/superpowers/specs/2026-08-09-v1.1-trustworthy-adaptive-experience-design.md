# PowerMode v1.1 可信执行与自适应体验设计

## 状态与目标

本设计覆盖 PowerMode v1.1 的下一轮打磨，合并两条相互依赖的主线：

- 让模式切换、状态读取和失败回滚具备稳定、可测试、可验证的执行边界；
- 在不增加功能复杂度的前提下，改善简单模式、响应式布局、当前状态表达和设置保存体验。

用户已批准采用渐进式混合重构，并授权按本文推荐值继续推进，无需逐项确认。

完成标准：

- GUI 不再通过解析面向用户的 CLI 文本判断状态或成功；
- 所有由 GUI 启动的子进程都有有限超时、取消和终止进程树行为；
- 模式切换以执行后的真实状态回读为最终依据；
- 配置损坏不会被静默覆盖，也不会触发基于默认值的外部副作用；
- 即使长期历史关闭，最近一次模式操作仍可撤销；
- 简单模式不再出现隐藏卡片留下的空槽或被拉伸的大块空面板；
- 主窗口在 720–1440 逻辑像素宽度和常见 DPI 下保持可用；
- 设置窗口不会因标题栏关闭而静默丢失修改；
- Release 测试、便携发布内容和构建来源由脚本自动校验。

## 约束与非目标

继续保留：

- WinUI 3、.NET 10、Windows App SDK 和 x64 自包含便携发布；
- Windows PowerShell 5.1 与 `powercfg` 作为系统操作基础；
- `PowerModeSwitcher.bat` 的现有入口、命令名称和默认人类可读输出；
- 简单/专业体验模式、四种标准预设、自动化、恢复中心和现有数据目录；
- 不增加生产运行时 NuGet 依赖。

本轮不做：

- 完整原生 C# 电源管理重写；
- 安装器、MSIX、Microsoft Store、WinGet、代码签名或自动更新交付；
- 新模式、新自动化条件或新的遥测采集；
- 首次启动向导、规则编辑器重做或复杂图表交互；
- MVVM 框架、依赖注入容器或数据库；
- 对现有配置、历史、备份和 CLI 命令进行破坏性迁移。

## 总体架构

采用“兼容入口 + 结构化脚本契约 + C# 事务编排”的混合结构。

### PowerShell 引擎与 BAT 兼容入口

新增 `src/PowerMode.Cli/PowerMode.Engine.ps1`，作为 PowerShell 实现的唯一来源。现有 `PowerModeSwitcher.bat` 缩减为定位并调用该脚本的兼容启动器。

默认调用继续输出当前中文或英文文本。GUI 和自动化测试使用显式 JSON 格式参数；JSON 契约包含：

- `schemaVersion`，首版固定为 `1`；
- `operationId`、`action`、`requestedMode`、开始时间和耗时；
- 总体 `outcome`；
- 每个步骤的名称、关键性、退出码、超时状态和简短错误；
- 可读取时的操作前后电源状态；
- 适用于该操作的验证期望。

脚本只在最后写出一个完整 JSON 文档，诊断文本进入步骤消息或标准错误，不能与 JSON 混排。未知 `schemaVersion` 必须被 GUI 拒绝并显示契约不兼容，而不是退回文本解析。

便携包在根目录同时放置 BAT 和 PowerShell 引擎。GUI 直接调用同一引擎；开发环境兼容查找源码路径。正常发布路径不再从 BAT 按时间戳抽取临时脚本。若开发兼容路径需要落地临时副本，只能以 SHA-256 内容哈希作为身份，并在执行前再次核对哈希。

### 统一进程执行器

新增职责单一的 `IProcessRunner` 和实现 `ProcessRunner`：

- 异步读取标准输出与标准错误，避免同步 `ReadToEnd` 或 `WaitForExit` 阻塞 UI；
- 每次调用必须提供有限超时；状态查询默认 10 秒，模式应用默认 30 秒，回滚默认 20 秒；
- 支持 `CancellationToken`，超时或取消时终止整个进程树；
- 返回 `ProcessExecutionResult`，包含退出码、输出、错误、耗时、超时和取消标记；
- 进程启动失败也转换为结果，不直接泄漏到 UI 事件处理器；
- 原始输出只进入专业日志或诊断信息，不参与业务判断。

监控、状态刷新、诊断和模式切换逐步共用该执行器。长耗时诊断可以传入自己的有限超时，但不允许无限等待。

### 强类型后端与事务协调器

新增 `IPowerModeBackend`，提供状态读取、模式应用、验证和恢复所需的强类型方法。实现负责调用 JSON 契约并转换为 `PowerModeState`、`BackendOperationResult` 和步骤结果。

新增 `ModeSwitchCoordinator`，从 `MainWindow` 接管模式切换事务：

1. 生成操作 ID，并读取切换前快照；
2. 原子写入最近操作日志的 `Prepared` 状态；
3. 执行目标模式，期间禁用重复模式操作；
4. 根据该模式实际修改的字段创建验证期望；
5. 回读活动方案及相关 CPU、亮度、关屏、睡眠和休眠值；
6. 分类最终结果；
7. 关键项失败时尝试恢复切换前的活动方案及可恢复设置；
8. 原子更新最近操作日志，并按用户偏好追加长期历史；
9. 将面向用户的摘要和面向诊断的步骤详情分别返回界面。

验证只检查本次操作声明会修改的字段。活动方案和该预设明确修改的 CPU、关屏、睡眠及休眠设置属于关键项；亮度在硬件能力未知或不支持时属于可选项。显式“远程 + 关闭 WiFi”中的 WiFi 失败产生 `Partial`，不会撤销已经成功的远程电源模式，以避免进一步破坏远程连接。

最终结果枚举：

- `Succeeded`：全部关键期望与真实回读一致；
- `Partial`：关键项成功，但至少一个可选项失败或不受支持；
- `Failed`：关键项失败，且回滚已成功或无需回滚；
- `TimedOut`：执行超时，随后回读确认目标未完整生效；
- `RollbackFailed`：目标失败且无法确认恢复到操作前状态；
- `Cancelled`：仅限系统关闭或调用方在开始修改前取消；一旦进入修改阶段，用户重复点击不会中断事务。

进程退出码为零只是步骤证据之一，不能单独产生 `Succeeded`。

## 配置加载与恢复

### 显式配置加载状态

`SettingsStore` 增加不抛出到 UI 的显式加载结果：

- `FirstRun`：配置文件不存在；
- `Loaded`：当前格式正常；
- `Migrated`：旧格式已归一化；
- `Corrupt`：文件存在但无法读取、解析或归一化。

遇到 `Corrupt` 时：

- 将原文件原样复制为带 UTC 时间和内容哈希的隔离副本；
- 不覆盖原文件，直到用户选择恢复备份或重置；
- 仅使用内存中的安全默认值渲染界面；
- 不执行开机启动注册、自动切换、应用上次模式或其他基于默认值的外部副作用；
- 主窗口显示不可忽略的恢复提示，并提供打开恢复中心的操作。

首次启动仍可正常写入默认配置，不显示损坏警告。

### 最近操作日志

新增 `%LOCALAPPDATA%\PowerMode\last-operation.json`，只保留最近一次改变系统状态的操作。它属于恢复元数据，不属于长期历史或遥测，因此不受“记录操作历史”偏好控制。

日志采用临时文件 + 原子替换写入，包含：

- 操作 ID、来源、原因、目标模式和时间；
- 操作前快照；
- `Prepared`、`Applying`、`Verified`、`RolledBack` 或 `Uncertain` 状态；
- 最终结果与回滚结果。

恢复中心优先使用该日志提供一键撤销。长期 JSONL 历史继续服务洞察和审计，但写入时不再扫描完整文件判重；进程启动时建立最近 ID 集合，追加时更新计数，超过固定的 2,000 条上限后再原子整理为最近 2,000 条。

应用启动时发现 `Prepared`、`Applying` 或 `Uncertain` 记录，将先读取真实系统状态，再显示“验证当前状态”或“恢复操作前状态”；不会自动猜测成功，也不会在后台自动回滚。

## 自适应与清晰体验

### 主窗口布局

保留现有视觉语言、Mica、主题资源和单窗口结构，新增纯逻辑 `ResponsiveLayoutPolicy`，根据逻辑宽度和体验模式返回布局状态，便于单元测试。

断点：

- `Wide`：宽度不小于 1040；
- `Medium`：宽度 760–1039；
- `Narrow`：宽度小于 760，最低支持宽度 720。

行为：

- 状态卡片按当前可见卡片重新从左到右排列；Wide 为三列，Medium 为两列，Narrow 为一列，不再因 GPU、亮度等卡片隐藏留下空槽；
- 专业模式 Wide 保留左侧模式面板和右侧日志，Medium/Narrow 改为上下堆叠并给予日志有限最小高度；
- 简单模式的模式面板使用内容高度并顶部对齐，不再把边框拉伸填满整个剩余窗口；
- Wide 显示完整工具栏文字，Medium 显示主要文字和次要图标，Narrow 将专业次要操作放入“更多”菜单；体验模式、恢复和语言始终可达；
- 保留用户保存的窗口大小，不因切换简单/专业模式强制缩放；
- 默认窗口仍为 1120×760，最小窗口改为 720×560。

### 状态与模式表达

当前模式按钮不能只依赖强调色：

- 增加可见勾选标记和本地化“当前”徽标；
- 设置 `AutomationProperties.ItemStatus` 和可访问名称；
- 切换事务进行时四个模式按钮统一禁用，并在目标按钮显示进度；
- `Partial` 使用警告图标和行动文本，`Failed`/`RollbackFailed` 使用错误图标，不以颜色作为唯一信息；
- 建议卡片命中当前模式时继续禁用应用按钮，但明确显示“当前模式”。

简单模式只显示结果摘要和恢复入口。专业模式保留结构化步骤详情，并允许复制诊断信息。

### 设置窗口

设置窗口增加统一脏状态：

- 初始加载和成功保存后为干净状态；任何可保存字段变化后为脏状态；
- 保存按钮仅在脏状态且输入有效时启用；
- 标题栏关闭、窗口内关闭按钮和快捷关闭走同一路径；
- 脏状态关闭时提供“保存”“放弃”“继续编辑”；
- 保存失败保持窗口和脏状态，不丢输入；
- 删除自定义方案和规则前显示包含对象名称的确认；
- 中英文 Toggle、错误和确认文本使用同一字符串来源，移除可见的混合语言。

设置与洞察窗口在 760 逻辑像素以下将双列区域堆叠。CPU/亮度滑块和数值输入建立 `LabeledBy` 或明确自动化名称。洞察图表本轮不增加交互，但补充可访问摘要并将硬编码颜色替换为高对比度可用的主题资源。

## 错误呈现

界面使用两层错误信息：

- 摘要层：发生了什么、系统目前处于什么状态、用户下一步可以做什么；
- 诊断层：操作 ID、失败步骤、退出码、超时、回读差异和有限长度的原始输出。

摘要层不显示堆栈、脚本路径或整段标准错误。诊断层可从专业日志、复制诊断信息和恢复中心获取。

`RollbackFailed`、配置损坏和未完成事务必须保持可见，直到用户打开恢复中心、重新验证成功或明确关闭提示。普通刷新超时可以被下一次成功刷新取代。

## 监控与性能边界

硬件能力快照用于约束轮询：

- 未检测到 NVIDIA 时不启动 `nvidia-smi`；
- 无电池时不生成电池报告；
- 无受支持温度来源时不启动温度 PowerShell 探测；
- 同一种昂贵探测不会并发重入；
- 实时监控关闭时不保留后台采样进程；
- UI 状态刷新和推荐计算复用最近的有效快照，避免每十秒重复启动全部探测。

能力未知允许低频重试，但不能回到每个采样周期无条件探测。

## 测试策略

坚持先写失败测试，再实现行为。新增或扩展测试覆盖：

### 执行边界

- 正常完成、非零退出、启动失败、超时、取消和终止进程树；
- JSON 契约 v1 的成功、部分成功、错误和未知版本；
- 文本输出变化不会影响 GUI 解析；
- 模式事务的成功、可选项失败、关键项失败、回滚成功、回滚失败和执行后超时；
- 验证期望只检查本次声明修改的字段；
- 并发点击不会产生并行模式事务。

### 配置与恢复

- 首次启动、正常加载、旧格式迁移和损坏配置；
- 损坏文件被隔离且原文件未被覆盖；
- 损坏状态不执行启动注册或自动模式副作用；
- 最近操作日志的原子写入、未完成事务检测和历史关闭下的一键撤销；
- 历史追加不进行全文件判重，且保留数量有界。

### 呈现与可访问性

- Wide、Medium、Narrow 的布局策略；
- 任意能力卡片隐藏后的连续排列；
- 简单/专业模式的内容列和工具栏状态；
- 当前模式同时具有颜色之外的可见标记和自动化状态；
- 设置脏状态、关闭选择、保存失败保留输入和删除确认；
- Settings、Insights 的滑块标签、高对比度资源和可访问摘要。

### 集成与回归

- 现有全部测试继续通过；
- Release x64 构建与自包含 publish；
- 默认 CLI 文本命令保持兼容；
- GUI 使用 JSON 契约完成状态刷新和四种预设；
- 配置损坏、子进程超时和回滚失败的人工冒烟；
- 浅色、深色、高对比度，100%、125%、150% DPI；
- 720、760、960、1040、1120 和 1440 逻辑像素宽度。

## 发布与来源校验

`Publish-Portable.ps1` 默认先运行 Release 测试，再执行 publish。仅本地诊断场景允许显式 `-SkipTests`，该参数不得用于正式发布说明中的命令。

便携发布新增校验：

- BAT、PowerShell 引擎和 README 与源码 SHA-256 一致；
- `App` 中不存在 PDB、测试程序集或中间文件；
- `PowerMode.exe` 可读取产品版本；
- `build-info.json` 包含版本、Git 提交、构建时间、运行时、可执行文件 SHA-256 和脚本 SHA-256；
- 创建 ZIP 时同时生成 `PowerMode-win-x64.zip.sha256`；
- 工作区有未提交修改时仍可本地构建，但 `build-info.json` 明确记录 `dirty: true`。

发布流程不在本轮自动创建标签、GitHub Release 或上传文件。

## 实施顺序

1. 建立进程执行器、JSON 契约模型和测试夹具；
2. 拆出 PowerShell 引擎并保持 BAT 文本兼容；
3. 实现强类型后端与模式事务协调器；
4. 实现显式配置加载、隔离和最近操作日志；
5. 将主窗口切换与刷新迁移到新边界；
6. 实现响应式布局、当前状态标记和结果呈现；
7. 修复设置保存语义、删除确认和可访问性缺口；
8. 按硬件能力收敛监控探测；
9. 强化便携发布脚本、文档和完整回归验证。

每一步都必须保持当前开发分支可构建，并在删除旧解析或抽取路径前证明新路径已有等价测试和实际回读验证。
